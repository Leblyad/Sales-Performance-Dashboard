# Что фиксировать в конфигурации

> Секции и порты, без которых агент поднимает сервис «как в прошлом проекте». Секреты сюда не копировать.

## Context

Приёмочный запуск — `docker compose up --build`, см. [[Разбор задания/01 Онбординг/Запуск и сдача]]. Корневой `docker-compose.yml` поднимает `postgres` и `api`. Локальный `dotnet run` шаблона — не этот путь.

## Details

Когда появятся `docker-compose.yml` и конфиг backend/frontend, записать:

- имена сервисов compose и кто от кого зависит;
- порты снаружи (браузер, API, PostgreSQL);
- имена секций конфигурации (`ConnectionStrings`, и что добавится под dashboard);
- что задаётся переменными окружения, а что файлом;
- какие значения — только для локального compose.

Пароли и строки подключения с секретами не вставлять. Достаточно имени переменной и примера без секрета.

Сервисы корневого compose: `postgres` и `api`. `api` зависит от `postgres` с условием `service_healthy`. Сервиса frontend нет.

Порты снаружи: PostgreSQL `5432`, API `8080`.

Секция `ConnectionStrings`, ключ `DefaultConnection`, файл `backend/SalesDashboard.Api/appsettings.json`. База `sales_dashboard`. В контейнере `api` та же строка задаётся переменной `ConnectionStrings__DefaultConnection`: хост — имя сервиса `postgres`, порт `5432`, та же база и тот же пользователь. Пароль в эту заметку не копируется. Хост `postgres` и эти порты — для локального compose.

В этот compose не входят:

- `frontend/Dockerfile` — сборка Vite, nginx отдаёт `dist`. Внутри контейнера порт 80. Для локальной проверки снаружи — 5173.
- `VITE_API_BASE_URL` задаётся на сборке клиента. Пример без секрета — `frontend/.env.example`. В образ заглушки переменная не передаётся: запрос dashboard в коде выключен.

Образ `backend/SalesDashboard.Api/Dockerfile` собирает сервис `api` и слушает 8080. С клиентом он не связан.

## Decisions

Имена сервисов compose — `postgres` и `api`. Пароль в vault не хранится.
