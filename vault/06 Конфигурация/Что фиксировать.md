# Что фиксировать в конфигурации

> Секции и порты, без которых агент поднимает сервис «как в прошлом проекте». Секреты сюда не копировать.

## Context

Приёмочный запуск — `docker compose up --build`, см. [[Разбор задания/01 Онбординг/Запуск и сдача]]. Файла compose в репозитории ещё нет. Локальный `dotnet run` шаблона — не этот путь.

## Details

Когда появятся `docker-compose.yml` и конфиг backend/frontend, записать:

- имена сервисов compose и кто от кого зависит;
- порты снаружи (браузер, API, PostgreSQL);
- имена секций конфигурации (`ConnectionStrings`, и что добавится под dashboard);
- что задаётся переменными окружения, а что файлом;
- какие значения — только для локального compose.

Пароли и строки подключения с секретами не вставлять. Достаточно имени переменной и примера без секрета.

Уже есть, без compose:

- `frontend/Dockerfile` — сборка Vite, nginx отдаёт `dist`. Внутри контейнера порт 80. Для локальной проверки снаружи — 5173.
- `VITE_API_BASE_URL` задаётся на сборке клиента. Пример без секрета — `frontend/.env.example`. В образ заглушки переменная не передаётся: запрос dashboard в коде выключен.
- `backend/SalesDashboard.Api/Dockerfile` слушает 8080. Это отдельный образ API, не связанный с клиентом.

## Decisions

Имена сервисов compose, PostgreSQL и URL проверяющего пока не зафиксированы.
