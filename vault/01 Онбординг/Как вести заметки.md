# Как вести заметки

> Куда класть результат работы, чтобы агент и README смотрели в одно место.

## Context

Vault — каталог `vault/` в репозитории. Точка входа — [[00 Индекс]]. Разбор ТЗ лежит отдельно и не заменяет документацию реализации.

## Details

| Что произошло | Куда писать |
|---------------|-------------|
| Закрыли пункт из [[Разбор задания/03 Домен/Открытые решения]] | Заметка в `03 Домен/` по [[Шаблоны/Бизнес-правило]], строка в [[03 Домен/Принятые правила]], статус в таблице разбора |
| Выбрали библиотеку, слой, SQL вместо ORM | Заметка в `02 Архитектура/` по [[Шаблоны/Решение]] и строка в [[02 Архитектура/Журнал решений]] |
| Появился endpoint | Заметка в `05 API/` по [[Шаблоны/API-контракт]] и строка в [[05 API/Контракты]] |
| Появились compose, порты, секции конфига | [[06 Конфигурация/Что фиксировать]] |
| Появилась миграция домена продаж | [[17 Миграции БД/Что фиксировать]] |
| Заработал `docker compose up --build` | [[12 Ранбуки/Локальный запуск]] |
| Появился индекс или осознанный raw SQL | [[18 Производительность/Индексы и выборки]] |
| Написали тест на KPI, период, рейтинг, статус, смену периода или loading/error | [[09 Тестирование/Что покрыто]] |
| Сдвинулся этап из ТЗ | [[13 PM/Прогресс]] по [[Шаблоны/Запись прогресса]] |
| Не успели блок за timebox | [[21 Техдолг/Не успели]], той же фразой потом в README |
| Отправили запрос модели | `AI_PROMPTS.md` в корне репозитория, не сюда. Итог сессии — `AI_NOTES.md`. См. [[22 AI Контексты/Рабочий журнал]] |

Один факт — одна заметка. В разбор задания ход работы не дописывать.

README в корне собирается из уже записанного: запуск из ранбука, business rules из `03 Домен/`, индексы из раздела производительности, «не успели» из техдолга.

## Decisions

Служебные файлы Obsidian не синхронизируем отдельно: хранилище едет вместе с репозиторием.
