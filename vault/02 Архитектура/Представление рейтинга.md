# Представление рейтинга

> Рейтинг менеджеров читается из представления: одна строка на менеджера, GrossProfit и AverageCheck только по Paid.

## Context

Рейтинг повторяет формулы [[03 Домен/Состав KPI]] с группировкой по менеджеру. Считать те же суммы отдельно в запросе приложения значило бы развести формулу с `kpi_cards`.

## Details

- Варианты: запрос LINQ по продажам или представление PostgreSQL, которое EF читает как модель без ключа.
- Выбрано: представление `manager_rankings`. CTE в миграции `ManagerRanking` собирает только продажи со статусом Paid: Revenue продажи — сумма `Price * Quantity`, Cost продажи — сумма `SaleItem.Cost * Quantity`, группировка по продаже и менеджеру. Внешний запрос группирует по менеджеру. GrossProfit — сумма Revenue этих продаж минус сумма их Cost. AverageCheck — среднее их Revenue, как в [[03 Домен/Состав KPI]]. Cost одной продажи — [[03 Домен/Себестоимость]].
- Имя, аватар и `IsActive` берутся из `managers`, имя команды из `teams`, имя должности из `positions`. `IsActive` — столбец, не фильтр. Строка есть только у менеджера с хотя бы одной оплаченной продажей.
- Модель — `backend/SalesDashboard.Api/Data/Views/ManagerRanking.cs`, `ToView("manager_rankings")`, без ключа. DbSet — `ManagerRankings`.
- Цена: сортировки, номера места и сравнения с прошлым периодом в представлении нет. Таблицу миграция не создаёт. Индекса нет.

## Decisions

Отдельный запрос LINQ для этих двух показателей не заводится. Поля лучшего менеджера, Margin, Revenue и SalesCount в представление не входят. Пункты 4–10 в [[Разбор задания/03 Домен/Открытые решения]] остаются открытыми.
