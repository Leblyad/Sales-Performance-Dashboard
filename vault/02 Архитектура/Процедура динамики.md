# Процедура динамики

> Динамика одного менеджера — функция без CTE: строка на календарную дату, вызов через EF Core.

## Context

Динамика повторяет Revenue и GrossProfit из [[03 Домен/Состав KPI]] по одному менеджеру и по календарной дате. Считать те же суммы отдельным запросом в приложении значило бы развести формулу с `kpi_cards`.

## Details

- Варианты: запрос LINQ по продажам или функция PostgreSQL, которую EF читает как набор строк.
- Выбрано: функция `manager_dynamics` без CTE, `RETURNS TABLE`. Параметры `manager_id`, `date_from` и `date_to` есть в сигнатуре. Сравнения даты продажи с ними нет. Строка — календарная дата. На ней Revenue, GrossProfit и число оплаченных продаж этого менеджера. Формулы те же, что в [[03 Домен/Состав KPI]], только по Paid. Cost позиции — [[03 Домен/Себестоимость]].
- Один SELECT по `sales` и `sale_items`. Только этот менеджер и `sale."Status" = 0`. Группировка по календарной дате продажи. Revenue — сумма `Price * Quantity` за день. GrossProfit — эта сумма минус сумма `SaleItem.Cost * Quantity` за день. Число продаж — `COUNT(DISTINCT sale."Id")`, не число позиций. Дни без оплаченных продаж не заполняются.
- Вызов — `Database.SqlQuery` в `backend/SalesDashboard.Api/Data/Queries/ManagerDynamicsQuery.cs`: `SELECT * FROM manager_dynamics(manager_id, date_from, date_to)`. Результат — набор строк.
- Представления и DbSet для этой динамики нет. Таблицу миграция не создаёт. Индекса нет.
- `kpi_cards` тоже без CTE, значения полей те же.

## Decisions

AverageCheck, Margin, лучший менеджер, фильтр `IsActive`, категории и рейтинг в функцию не входят. Пункты 4–10 в [[Разбор задания/03 Домен/Открытые решения]] остаются открытыми.
