# Клиент

> Стек выбран. Интерфейсы ответов отдельно от вызовов. Выбор периода в Zustand. Ответ KPI за период тоже хранится там: повторно этот период не запрашивается.

## Context

Требования к странице — [[Разбор задания/04 Dashboard/Экран]] и [[Разбор задания/04 Dashboard/Состояния и граничные случаи]]. Считать KPI в браузере нельзя, см. [[Разбор задания/05 API/Требования]].

Правила и список библиотек — `frontend/react-client.md`. Почему так — [[02 Архитектура/Стек клиента]].

## Details

Уже решено:

- React 19, TypeScript, Vite, TanStack Router, TanStack Query, Zustand, Zod, React Hook Form, Tailwind, shadcn/ui, Vitest, Testing Library, Playwright, MSW, ESLint, Prettier;
- одна страница в браузере около 1440×900, без mobile и без входа.

Каркас экрана:

- корневой layout — боковое меню и область страницы;
- один маршрут `/`, меню переключает одну вкладку через search-параметр `section`: `kpi`, `ranking`, `dynamics`, `categories`, `products`, `sales`;
- без параметра и при чужом значении открыта вкладка `kpi`; на экране видна только она;
- тема синий и белый, стили через Tailwind;
- функции шести GET лежат в `frontend/src/features/dashboard/services/` и ходят на `/api` своего origin;
- интерфейсы ответов и параметров — `frontend/src/features/dashboard/entities/`, отдельно от вызовов;
- общее состояние экрана (период KPI, режим категорий, менеджер динамики, skip и take категорий и последних продаж) — Zustand в `frontend/src/features/dashboard/stores/`. Ответ `GET /api/dashboard/kpi` кладётся в этот store по паре дат. Если пара уже есть, запрос не отправляется. Ответ `GET /api/dashboard/ranking` кладётся по режиму, skip и take. Если эта тройка уже есть, запрос не отправляется. Режим, страница, график рейтинга и его дата в store не пишутся. Вкладка `section` остаётся search-параметром маршрута;
- начальные значения: вид периода KPI — 7 дней; `periodFrom` и `periodTo` — сегодня и шесть дней назад, локальный календарь браузера, обе границы включительно, строки `YYYY-MM-DD` без времени; `categoryMode` 0 — количество продаж; `skip` 0; `take` 10 из набора 10/25/50. На вкладке рейтинга свой режим Gross Profit, своя страница по 10 и свой период графика — те же 7 дней; серия графика начинается с Revenue;
- в store хранится вид периода: сегодня, 7 дней, 30 дней, этот месяц, прошлый месяц, произвольный. 30 дней — сегодня и 29 дней назад. Этот месяц — с первого по последний день текущего месяца. Прошлый месяц — с первого по последний день предыдущего месяца. Произвольный диапазон — календарь в цветах темы: две даты, вид `custom`, даже если даты совпали с пресетом. Запрос KPI уходит, когда обе даты существуют и начало не позже окончания. Пока конец не выбран, числа периода не показываются;
- вкладка KPI показывает селектор периода и шесть блоков: выручка, валовая прибыль, маржинальность, количество продаж, средний чек, лучший менеджер. Cost отдельным блоком не показывается. Текущий период — один запрос `GET /api/dashboard/kpi` с `PeriodFrom` и `PeriodTo` из store. Для пресета второй такой запрос идёт за предыдущее окно той же длины, сразу перед текущим; у произвольного диапазона его нет, приписка не показывается. Разница округлённых значений и её процент в скобках пишутся на числовой карточке. Лучший менеджер — `GET /api/dashboard/ranking` с Mode 0, Skip 0, Take 1; переключатель рейтинга этот Mode не меняет. Для «сегодня» на экране одна дата. Вызовы идут через axios в `frontend/src/lib/api.ts`;
- вкладка рейтинга: таблица на высоту секции. Переключатель Gross Profit и Average Check, страница и размер 10/25/50 живут в состоянии секции, не в store. Колонки — аватар, имя, команда, должность и значение выбранного показателя. Тело таблицы скроллится; смена страницы или размера возвращает скролл наверх. Общего числа строк нет. Клик по строке открывает справа график этого менеджера и сужает таблицу. Кнопка «Скрыть» убирает график, таблица снова на всю ширину;
- график — Recharts, линия. Показатель серии и период (те же пресеты и произвольный календарь, что у KPI) живут в состоянии графика, не в store. Календарь KPI и календарь графика тоже: открытие и первая выбранная дата сбрасываются вместе с секцией. Календарь закрывается после второй даты и по клику мимо. Запрос `GET /api/dashboard/dynamics` с `ManagerId`, `DateFrom`, `DateTo`. Числа на оси слева, даты снизу. Наведение на точку показывает её число. Ответ динамики остаётся в TanStack Query;
- страница рейтинга с тем же режимом, skip и take берётся из store и снова не запрашивается. KPI за уже загруженный период тоже. График динамики остаётся в TanStack Query. Вкладка «Динамика», категории, продукты и последние продажи API не вызывают. Продукты не сортируются: в контракте пять строк по Revenue.

`npm run dev` в `frontend/` открывает этот каркас на Vite. Его же можно собрать образом `frontend/Dockerfile`: nginx внутри слушает 80, локальная проверка открывает порт 5173. Это не URL готового dashboard и не команда сдачи.

Пока не заполнено:

- URL, который увидит проверяющий.
