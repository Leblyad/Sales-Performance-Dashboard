# Генерация seed

> Скрипт пишет SQL. Категории и товары не генерируются. Миграция `Seed` выполняет этот файл при `Database.Migrate()`.

## Context

Дашборду нужны менеджеры, клиенты и продажи за 12 месяцев. Скрипт по-прежнему только пишет файл. В базу строки попадают один раз, вместе с остальными миграциями.

## Details

- Варианты: отдельный проект .NET, ручной запуск файла, выполнение файла миграцией.
- Выбрано: `backend/seed/generate-seed.ps1` с фиксированным зерном пишет `backend/seed/seed.sql` и к базе не подключается. Команды, должности, категории и товары — готовые INSERT в `backend/seed/reference.sql` с фиксированными uuid. Скрипт дописывает только менеджеров, клиентов, продажи и позиции продажи и берёт uuid справочника только из этого файла.
- Миграция `Seed`, файл `backend/SalesDashboard.Api/Migrations/20261002161931_Seed.cs`, читает `seed.sql` из сборки и выполняет его в `Up`. `Down` удаляет строки этих таблиц. Применяется в `backend/SalesDashboard.Api/Program.cs` вызовом `Database.Migrate()`.
- 20 менеджеров, 80 клиентов, 3000 продаж с 2025-10-01 по 2026-09-30 включительно. У Refunded в Price записана полученная часть, Cost и Quantity как у обычной позиции: [[03 Домен/Возврат]].
- Смещение `+00` в timestamp нужно, чтобы повторный запуск скрипта давал тот же файл. Сравнение по дате или по времени и часовой пояс этим не закрыты. Диапазоны цен не закрывают масштаб денег.

## Decisions

Отдельный проект и отдельный шаг в docker compose отвергнуты. Файл выполняет миграция `Seed`, а не ручной запуск. Сравнение по дате или по времени, часовой пояс и пункты 6–10 остаются открытыми.
