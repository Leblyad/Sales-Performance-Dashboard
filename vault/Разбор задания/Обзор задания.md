# Обзор продукта

> Desktop-dashboard аналитики продаж менеджеров для B2B. Одно приложение, локальный запуск одной командой.

## Context

Тестовое задание DJI-Market.ru, роль Middle Full-Stack / AI-Native. Ориентир по времени — 8 часов фактической работы. После восьми часов система должна остаться рабочей; недоделанное честно описывается в README, а не маскируется незакрытыми идеями.

Проверяют не синтаксис и не «карточки». Смотрят, как целиком закрыта продуктовая задача: модель, API, PostgreSQL, React, ошибки и пустые состояния, тесты, работа с AI и проверка его результата.

## Details

В `backend/` уже лежит скелет шаблона сервиса, не dashboard. Каталога `frontend/` и `docker-compose.yml` ещё нет.

После `git clone` проверяющий выполняет только:

```text
docker compose up --build
```

Дальше сам поднимаются frontend, backend и PostgreSQL, применяются миграции, появляется seed, в браузере открывается уже заполненный dashboard. Отдельный SQL, ручной seed, установка зависимостей руками — минус.

| | |
|---|---|
| Frontend | React, TypeScript. Библиотеки на выбор |
| Backend | C#, .NET 8+, ASP.NET Core, EF Core, REST, async/await |
| Data | PostgreSQL, миграции обязательны |
| Run | Docker Compose |
| UI | Desktop, целевой viewport около 1440×900. Mobile не нужен |
| Авторизация | Нет. Пользователь уже «вошёл» |
| AI | Можно и нужно. Код, который автор не может объяснить, не засчитывается |

Ожидаемый корень репозитория (можно иначе, если понятнее):

```text
/frontend
/backend
docker-compose.yml
README.md
AI_PROMPTS.md
AI_NOTES.md
```

## Decisions

Зафиксировано ТЗ, не нами:

- Авторизацию не делать.
- Считать и фильтровать на сервере. Тысячи продаж в браузер для пересчёта dashboard не отправлять.
- Clean Architecture, CQRS и Repository не обязательны. Лишний слой — только если закрывает конкретную проблему.
- Не успеть часть блоков нормально, если ядро запускается и это написано в README.
