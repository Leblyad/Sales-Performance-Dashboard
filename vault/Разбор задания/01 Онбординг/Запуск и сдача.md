# Запуск и сдача

> Что должно лежать в README и в истории git, чтобы проект приняли без переписки с автором.

## Context

Проверяющий клонирует репозиторий и не настраивает окружение вручную. README — единственная инструкция.

## Details

### Запуск

Одна команда: `docker compose up --build`.

Цепочка, которая должна произойти сама: контейнеры frontend, backend, PostgreSQL → миграции EF Core → seed → dashboard в браузере с данными.

### README обязан содержать

- точную инструкцию запуска;
- кратко: frontend, backend, БД, API;
- business rules: Revenue, Gross Profit, Refund, Cancelled и предыдущий период;
- основные технические решения и индексы;
- что не успели за 8 часов;
- что улучшили бы в production.

Формулировки Refund / Cancelled / предыдущий период берутся из принятого правила в [[Разбор задания/03 Домен/Открытые решения]]. Пока решение не принято, в README его не выдумывать.

### Git

Не один финальный коммит на всё и не пятьдесят мелких. Ориентир этапов из ТЗ:

1. initial project structure
2. add sales domain and seed
3. implement analytics API
4. build dashboard UI
5. add charts and animations
6. add tests
