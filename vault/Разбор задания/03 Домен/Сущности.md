# Сущности

> Минимальная модель, чтобы dashboard выглядел как часть B2B-продукта, а не как три карточки.

## Context

Имена сущностей заданы ТЗ. Поля «необходимые атрибуты» у товара и точный набор полей менеджера ТЗ не закрывает — не раздувать модель полями, которые не участвуют в экране и в seed.

## Details

| Сущность | Что хранит по ТЗ |
|----------|------------------|
| Manager | Имя, команда или должность, активность, данные для avatar/initials |
| Customer | Имя, компания, сегмент |
| Category | Категория товаров |
| Product | Название, категория, атрибуты, без которых нельзя посчитать себестоимость позиции |
| Sale | Менеджер, клиент, дата, статус |
| SaleItem | Товар, количество, цена продажи, себестоимость |

Связи, которые следуют из списка: Sale → Manager, Sale → Customer, Sale → SaleItem → Product → Category.

Статусы продажи и формулы — [[Разбор задания/03 Домен/Показатели и статусы]]. Объёмы seed — [[Разбор задания/06 Данные/Seed и PostgreSQL]].

Активность менеджера в ТЗ названа, но не определена (уволен, не принимает заказы, просто флаг). Пока нет сценария на экране, отдельное правило не выдумывать. Если флаг нигде не фильтрует рейтинг — так и записать в решении.

## Decisions

Состава полей сверх таблицы выше нет. Avatar/initials нужны UI рейтинга и списка продаж, это не отдельная фича профиля.
