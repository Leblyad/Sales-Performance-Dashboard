# Модель

> Форма классов домена продаж: Guid Id, отдельные Team и Position, Avatar как URL, пара «Id + объект» у ссылающейся стороны, без Initials.

## Context

Классы лежат в `backend/SalesDashboard.Api/Domain/`. Снимок полей из ТЗ — [[Разбор задания/03 Домен/Сущности]]. Из кода одной продажи не видно, что команда и должность — отдельные сущности, что Avatar — строка URL и поля Initials нет, и на какой стороне хранится Id связи. Трактовки KPI эта форма не задаёт.

## Details

У каждой сущности `Id` типа `Guid`.

| Тип | Поля |
|-----|------|
| Team | Id, Name |
| Position | Id, Name |
| Manager | Id, Name, TeamId, Team, PositionId, Position, IsActive, Avatar |
| Customer | Id, Name, Company, Segment |
| Category | Id, Name |
| Product | Id, Name, CategoryId, Category |
| Sale | Id, ManagerId, Manager, CustomerId, Customer, Date (`DateTime`), Status, Items |
| SaleItem | Id, SaleId, Sale, ProductId, Product, Quantity (`int`), Price (`decimal`), Cost (`decimal`) |
| SaleStatus | Paid, Cancelled, Refunded |

`Avatar` — строка URL. Поля `Initials` нет.

Id связи — `Guid` и стоит рядом с навигацией только у стороны, которая ссылается на другую сущность: Manager → Team и Position, Product → Category, Sale → Manager и Customer, SaleItem → Sale и Product. У Team, Position, Customer и Category коллекций обратной стороны нет. У Sale нет списка Id позиций: Id позиции лежит на `SaleItem.SaleId`.

Себестоимость позиции — `SaleItem.Cost`. Отдельных атрибутов товара нет. `SaleStatus` — только поле статуса. Выручка, количество и прибыль здесь не считаются.

## Decisions

Форма таблицы выше — состав классов домена. Конфигурация EF лежит в `backend/SalesDashboard.Api/Data/Configurations`. Seed и миграция в эту заметку не входят.

Пункты 1–3 приняты в [[03 Домен/Принятые правила]]. Пункты 4–10 в [[Разбор задания/03 Домен/Открытые решения]] остаются открытыми: деление на ноль, границы периода, прошлый период, ничья в рейтинге, лучший менеджер, активность менеджера, масштаб денег.
