# Sales Performance Dashboard

Экран продаж для руководителя: KPI, рейтинг менеджеров, график одного менеджера и категории. Считают агрегаты сервер и PostgreSQL.

## Запуск

Из корня репозитория:

```bash
docker compose up --build
```

Поднимаются PostgreSQL, API и экран. Миграции EF Core, включая загрузку seed, выполняются при старте API до приёма запросов. Отдельная команда для базы не нужна.

- Экран: http://localhost:5173
- API: http://localhost:8080/health
- Swagger: http://localhost:8080/swagger

Сброс базы: `docker compose down -v`, затем снова `docker compose up --build`. Seed загрузится миграцией заново.

## Стек

- Frontend: React 19, TypeScript, Vite. В контейнере nginx слушает 80, снаружи порт 5173.
- Backend: один проект ASP.NET Core, EF Core. Снаружи порт 8080.
- База: PostgreSQL 17, база `sales_dashboard`, снаружи порт 5432.

API dashboard:

| Блок | Метод |
|------|--------|
| KPI | `GET /api/dashboard/kpi` |
| Рейтинг | `GET /api/dashboard/ranking` |
| Динамика менеджера | `GET /api/dashboard/dynamics` |
| Категории | `GET /api/dashboard/categories` |
| Пять продуктов | `GET /api/dashboard/products` |
| Последние продажи | `GET /api/dashboard/sales` |

## Правила

Revenue, Cost, GrossProfit, Margin, SalesCount и AverageCheck считаются только по Paid. Revenue одной продажи — сумма `Price * Quantity` по её позициям. GrossProfit — Revenue − Cost. Margin — GrossProfit / Revenue. SalesCount — число этих продаж. AverageCheck — среднее их Revenue. Продажи не в статусе Paid в эти поля не входят, поэтому Cancelled в них не входит.

Refunded — возврат. По нему может быть получена только часть исходной суммы. Эта часть записывается в Price соответствующей позиции SaleItem, а статус продажи становится Refunded. Price после возврата — полученные средства, не сумма, которую вернули покупателю. Cost и Quantity этим правилом не меняются. В шесть полей KPI Refunded не входит.

Cost продажи с несколькими позициями — сумма `SaleItem.Cost * Quantity` по её позициям. В KPI эта сумма берётся только у Paid.

from и to включительны. Продажа на границе from и продажа на границе to входят в период.

Для пресета предыдущее окно имеет ту же длину и стоит сразу перед текущим. Сегодня — это вчера. Произвольный диапазон не сравнивается.

На экране число показывают с двумя знаками после запятой. Тысячи разделяют пробелом. Маржу на 100 не умножают.

При делении на 0 или null вычисляемое поле остаётся null.

## Технические решения

KPI считается функцией `kpi_cards`, динамика менеджера — функцией `manager_dynamics`. Обе вызываются через EF Core. Рейтинг читается из представления `manager_rankings`. Категории, пять продуктов и последние продажи — запросы LINQ.

Индексов под эти агрегаты нет. В схеме есть индексы внешних ключей.

Backend-тесты шести запросов dashboard прогнаны командой `dotnet test SalesDashboard.slnx` из `backend/`. Frontend-тесты смены периода, режима рейтинга, загрузки и ошибки прогнаны командой `npm test` из `frontend/`.

## Не успели

| Что отложено | Почему сейчас не делается | Что сделать в production |
|--------------|---------------------------|--------------------------|
| Одна страница со всеми блоками сразу | Экран разбит на вкладки KPI, рейтинг и категории | Собрать блоки на одном экране около 1440×900 |
| Общий период для рейтинга, продуктов и последних продаж | Рейтинг и пять продуктов считаются по всем оплаченным продажам. Список продаж открывается из категории и по периоду не режется | Пропустить тот же from–to во все агрегаты экрана |
| График по компании | Линия есть только у выбранного менеджера | Добавить динамику без фильтра по одному менеджеру |

## В production

Задать часовой пояс и сравнение даты со временем, ничью в рейтинге, правило для неактивного менеджера и масштаб денежных колонок. Добавить индексы под фильтр периода и статус, если объём вырастет сверх seed. Вынести прогон тестов в CI.
